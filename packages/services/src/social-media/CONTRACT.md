# Social media service contract

The Host owns the account-scoped media catalog, download jobs, and managed originals. The public service returns metadata only; it never returns source or managed absolute paths. `preparePreview({ accountId, mediaId })` validates both ownership records, privately resolves the managed original, and asks Main for a 30-minute opaque capability URL. The renderer receives the capability URL, MIME type, size, and expiry, but never the path. The Electron protocol resolves the token to the previously canonicalized regular file and retains native byte-range seeking. Capability URLs are ephemeral and are not persisted. All catalog and job reads and writes are filtered by account ID, and operations fail when the account does not exist. `catalog.json` accepts the legacy array format and writes version 1 `{ assets, jobs }` on its next mutation.

`importLocalFile` stores an immutable byte-for-byte copy and its metadata, then emits `onChanged`. A failed import leaves no visible item; staging and unreferenced files are removed during failure handling or the next locked catalog read. The user's source remains untouched. The renderer opens the native file picker through `IPlatformService` and passes the selected path to this service; it must not access Node filesystem APIs or `window.zcode` directly. The path is transient input and is never persisted or returned.

`searchYouTube` trims and validates the query, invokes the Host's yt-dlp adapter for at most ten flat metadata results, validates every video ID and metadata field, and constructs canonical YouTube URLs from validated IDs. It is read-only: results belong to the renderer's transient query state and search never writes the catalog, downloads media, or emits `onChanged`. Missing metadata remains `null`, duplicate or malformed records are omitted, and failures are retryable. The adapter disables user configuration and cache, explicitly uses the Host's Node runtime for YouTube JavaScript challenges, uses no shell, runs outside the workspace, and bounds runtime and output size. Desktop packaging stages a pinned official yt-dlp standalone binary with its bundled `yt-dlp-ejs` code, verifies SHA-256, and includes upstream license materials; the Host resolves this asset without relying on user `PATH`. `SOCIAL_HARNESS_YT_DLP_PATH` remains a development/runtime override and may point to an `.mjs` fixture launched through the Host Node executable under the same shell-free adapter limits.

`suggestClipCandidates` requires a valid account and an asset owned by it. Podcast mode ranks complete transcript cues, nearby pauses, and any overlapping YouTube heatmap segments; without usable transcript cues it returns no suggestions with `transcript-unavailable`. Music mode never reads or invents speech. It uses ffprobe to validate streams and duration, then streams mono 4 kHz audio and (for video) 32×18 grayscale frames sampled every two seconds through FFmpeg. Audio energy/onset and periodicity plus measured frame changes become explicit evidence. The Host returns at most five deterministic 15–60 second ranges for user review. These results are transient, are never written to the catalog, and do not emit `onChanged`. Images, sources without audio, and media over two hours return an unavailable reason. ffprobe and FFmpeg processes run without a shell, with a 15-second probe timeout, a 90-second analysis timeout, and bounded stdout; source and generated frame bytes are not persisted. `SOCIAL_HARNESS_FFPROBE_PATH` is a development/runtime override; packaged installs must provide ffprobe alongside FFmpeg.

`downloadSourceUrl` accepts one HTTPS source supported by yt-dlp. YouTube watch, shorts, embed, live, and short-link forms normalize to the canonical watch URL; playlists and malformed IDs fail validation. Other supported extractors accept HTTPS URLs without credentials, fragments, alternate ports, or query keys commonly used for credentials. yt-dlp runs without user config, cookies, cache, or playlist expansion. Every downloader HTTPS connection—including redirects and CDN requests—must use a short-lived loopback-only CONNECT proxy that resolves and pins a public unicast address on port 443, rejecting private, loopback, link-local, reserved, and malformed targets. Raw non-YouTube source URLs are not logged or returned to the Social Agent. The canonical YouTube video ID or SHA-256 hash of a canonical non-YouTube URL is the per-account idempotency key; repeated requests return the existing job, including failed or completed jobs, without a second download. `retryJob` is the explicit retry path for failed and cancelled work.

The local file store uses a separate cross-process queue lock so only one Host instance runs the global serialized media queue across windows. Jobs and progress live in the catalog; the currently running subprocess handle is transient and belongs to the Host that acquired the queue lock. State changes persist before `onJobChanged`. Progress is checkpointed no more often than once per second. A second Host can still cancel by persisting `cancelling`; the owner polls that record and terminates the process tree. On acquiring the queue lock, a Host recovers interrupted `downloading`, `finalizing`, or `transcribing` jobs to `queued` and `cancelling` jobs to `cancelled`. Graceful Host shutdown terminates and awaits the process, then leaves the job queued; yt-dlp resumes partial data on the next run, while an already committed asset resumes analysis from its durable `mediaId`. Failed or cancelled work waits for an explicit retry.

The transcription model registry is multilingual and app-wide. `small` is the initial default; `tiny`, `base`, and `large-v3-turbo` are selectable alternatives. The Library exposes selection, installation progress, errors and cancellation without returning model paths. The Host verifies exact byte size and SHA-256 before atomically installing a model and persists the selected model in Social Harness data. A cross-process transfer lock gives one Host ownership of a download; progress and cancellation requests are durable so another window can observe or cancel it. Model installation is independent from per-account media job state; cancel and retry affect only the in-flight model download. The packaged `whisper-cli` is built from the checksum-pinned official whisper.cpp v1.9.4 source with static CPU-only settings; its license and source/build/binary checksums ship beside it. `SOCIAL_HARNESS_FFMPEG_PATH` and `SOCIAL_HARNESS_WHISPER_CPP_PATH` are development/runtime overrides; packaged installs resolve the fixed tool resource paths and must not require user configuration. FFmpeg/ffprobe 9.0.1 GPL runtime preparation is pinned for all six desktop targets; packaged builds must resolve the fixed resource paths, include the target shared libraries, and expose `libx264`. Corresponding-source publication and the complete dependency-license audit remain release gates.

The downloader receives only a normalized URL accepted by the Host, runs with `shell: false`, disables user config/cache and playlist expansion, routes network requests through the public HTTPS proxy, caps media output at 4 GiB, and uses a private per-job staging directory. Only regular, supported files directly inside that directory can be finalized. The store hashes the media and selected VTT subtitle sidecars, moves them into account-scoped managed storage, and atomically persists the asset and job as `transcribing` with its durable `mediaId`. The current subtitle selection is the account's BCP-47 language and English when available, with at most four VTT tracks. A pure WebVTT parser accepts only non-empty timed cues; if neither language has a valid track, the Host extracts mono 16 kHz audio with FFmpeg and runs local Whisper. Transcript segments and provenance are validated and persisted atomically with the `completed` job state. Missing tools or model leave the managed original intact and the job explicitly retryable. The adapter extracts only title, channel, duration, views, upload date, and validated heatmap segments from temporary info JSON; raw info JSON is deleted and never stored. Cancellation and download failures delete complete staging outputs, captions, and temporary metadata while retaining resumable `.part` files; cancellation or transcription failure preserves the managed original and retryable `mediaId`. Progress and failures expose no subprocess output or local paths.

`onJobChanged` is the continuous update path for clients attached to the Host running a job. Other windows read the same durable snapshot and reconcile it while jobs are active. Catalog events are emitted only after the file and asset metadata are durable.

Account deletion remains deferred until dependent conversations, media, projects, automations, credentials, and publications can be cleaned up in one coordinated operation. URL downloads and local transcription share the same Host-owned job lifecycle for YouTube and other supported HTTPS yt-dlp sources; unsupported or login-required sources fail retryably without partial catalog data.
