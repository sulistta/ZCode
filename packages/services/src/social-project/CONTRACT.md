# Social project service contract

The Host owns each account-scoped project document, revision history, command idempotency, and edit-control owner. The public service is the only accepted write path for both UI and Agent operations. `agentScope(workspaceIdentity)` resolves exactly one existing account and returns list/read/command operations bound to it; callers cannot supply an account ID or author. Agent scope rejects history and control-handoff commands. It stores only managed `mediaId` references and project metadata; renderer playhead, selection, in-progress gestures, and uncommitted settings-form values remain ephemeral. A refreshed read model with unchanged persisted settings must preserve the settings form draft; the form resets only when persisted settings values change.

Project mutations validate account ownership and media references through the social-account and social-media public contracts. Every command has an idempotency key and expected revision. Persistence of the new document and history record completes before `onChanged`; duplicate payloads return without a second write or event, reused IDs with another payload fail, and stale revisions do not mutate state.

Creation optionally accepts a stable request ID. The Host derives an account-scoped deterministic project ID and stores optional private creation metadata in the existing version-1 record. The catalog lock admits creation once: repeated matching requests return the current project without writing or emitting a second creation event, while changed content under the same request ID fails. Legacy records and UI creation without this key retain their behavior. The scoped Social Agent facade delegates creation and exact-revision export to this public service, with no model-supplied account ID, native path, approval or edit-control override.

User takeover is persisted and blocks Agent-authored edits until the user explicitly returns control. Undo and redo restore editor content as new monotonically increasing revisions. Read models return `canUndo` and `canRedo` from the same durable stacks, so clients do not infer history capabilities from visible history entries. Account deletion remains deferred, so project references are not orphaned by account removal.

The same Host service owns export job admission and lifecycle. `startExport` requires an exact accepted revision and request ID; it persists an immutable project snapshot before returning. Reusing the request ID with the same scope returns its existing job; reusing it for another project or revision fails. A single bounded worker serializes FFmpeg rendering, persists job changes before `onExportChanged`, and retries queued/rendering snapshots after Host restart after removing partial output. `cancelExport` terminates and awaits an active process tree. Completed exports retain a private Host path and a SHA-256 digest; public job records never include that path.

`prepareExportDownload` checks account ownership and completed status, then returns only a short-lived opaque local-media capability URL, expiry, and suggested filename. Desktop Main resolves the capability, shows the native save dialog, and copies the private file to disk. No renderer or Agent method accepts a native path or receives rendered bytes.
