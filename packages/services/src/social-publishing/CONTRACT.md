# Social publishing contract

The Host owns Instagram connection state, profile projections, and bridge-availability truth. Renderer may read only a boolean availability projection before enabling Connect or Reconnect; the bridge URL, Meta app configuration, and credentials never cross RPC. This module coordinates the short-lived OAuth handoff, verifies the Instagram profile, and asks the Main-owned credential adapter to persist tokens. The public contract returns only the availability boolean, authorization URL, opaque state, and non-secret connection/profile projection. Tokens, authorization codes, and app secrets are never returned through RPC.

Each pending authorization is bound to one account, a random state, and an in-memory PKCE verifier with a five-minute expiry. A handoff ticket is consumed at most once. The bridge issues a new account-scoped media-upload credential only while redeeming that ticket, so an unredeemed or expired ticket creates no media credential; it preserves any existing key while the Host verifies and commits the reconnect. Mismatched, expired, replayed, or failed callbacks do not report a connected account; the user must start a new flow. If the HTTPS adapter rejects a malformed handoff response but extracts a well-formed media credential, it best-effort revokes that credential before returning a sanitized error. If Host profile verification or local credential/profile persistence fails after redemption, the Host best-effort revokes only the new credential and preserves the prior local connection. After a successful local commit, the Host asynchronously best-effort revokes the previous credential. Disconnect removes local credentials and verified profile metadata without deleting the social account or dependent data, then uses the bridge's authenticated revoke-all operation to remove every media credential and temporary media lease for that account.

The Host refreshes an unexpired long-lived token when 14 days or less remain and it is at least 24 hours old. Refresh runs through a Host adapter and replaces the Main-owned encrypted credential while account state is serialized. A separate bridge media-upload credential is stored in the same OS-secure vault entry and is never sent through the renderer contract. A failed refresh preserves the current token until expiry; an expired token projects `reauth-required`. Disconnect and reconnect serialize with refresh so stale work cannot recreate an old credential; disconnect removes the local credential first, then best-effort revokes all bridge upload keys and temporary files.

For a connected account, the Host can read a bounded first page of the account's own Instagram media using the verified profile ID and the private credential. The public projection contains only validated media ID, type, caption, timestamp, and an Instagram permalink; it never includes the access token or follows a URL returned in pagination metadata. Media lookup is read-only and is not persisted as Social Harness account state.

The Host-only bridge adapter can stream a final MP4 as a Blob, with the account ID and SHA-256 digest, to the maintainer-operated bridge over HTTPS. The bridge verifies the digest and the 1 GiB object cap while streaming into a private temporary volume, then returns a two-hour capability URL and a separate cleanup lease only to the Host. Storage is capped at 2 GiB total and 32 leases, with one active upload per account. The public URL is constrained to the configured bridge origin before it can be passed to Meta; lease deletion is account-scoped and disconnect revocation removes that account's outstanding files. This is transport groundwork: a publish job must still bind the export hash and caption to explicit user approval and reconcile the Meta container before it can call this adapter.

Explicit Reel approval and the publication attempt are owned here. The service reads only completed export metadata from the social-project public contract and uses a Host-only artifact reader to stream and verify the local export; no file path or bytes cross the RPC boundary. It rejects a stale project revision, a changed digest, a caption outside Meta's limit, a duration outside 3 seconds–15 minutes, or a file above 1 GiB. A durable attempt is written before upload/container/publish side effects and is idempotent by request ID. Container status reads may resume after restart; a restart or unknown response while creating a container or calling `media_publish` becomes `reconciliation-required` and never repeats the POST. A user can resolve it as published only with a permalink verified against that connected account's recent media, or explicitly confirm that no post appeared; any new attempt then requires a new approval.

The service depends on the account contract for account existence. Bridge HTTP, profile verification, connection metadata persistence, and OS-secure credential access are adapters injected by the Host. The generic credential service is not a token store.
