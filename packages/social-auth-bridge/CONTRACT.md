# Social auth bridge contract

The production bridge is deployed into each user's dedicated Convex project. The maintainer operates no bridge. Convex owns only temporary OAuth state/tickets, hashed installation/account credentials and temporary approved media; Desktop/Host retains business state and secure Meta tokens. The Meta App Secret lives in that project's environment variables. [Full provisioning, auth, media and migration rules](../../specs/social-harness-convex.md).

The bundled official CLI deploys `src/adapters/convex` and calls an internal bootstrap mutation with a hash of the Host-generated installation credential. Provisioning keys are never daily authorization. The HTTP routes authenticate `x-social-installation` and additionally an account credential for media operations. Callback state is claimed once before external Meta requests. Success and denial both create an expiring installation/PKCE-bound ticket; redemption validates and consumes it atomically. Denial issues no account credential. Reconnect preserves prior account keys until Host verification/commit; disconnect revokes that installation/account's keys and media.

`POST /v1/media/reserve` creates an idempotent lease and authorized direct storage upload URL; `POST /v1/media/finalize` binds a validated storage object to the lease. `POST /v1/media/delete` removes the lease/object. Finalize/delete reject other installations/accounts. Scheduled expiry and an orphan sweep remove abandoned objects. Direct storage URLs are revoked by object deletion; provider outages can defer cleanup. The Free team's quotas and two-minute upload timeout are separate from the 1 GiB product file ceiling.

The earlier Node/Hono implementation in `src/app.ts`, its server/container and file-store tests remain as migration reference and regression fixtures. It is not a shipped hosting requirement, production bridge default or an operator task for the maintainer. There is no fallback to a central host.
