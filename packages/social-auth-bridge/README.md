# Social Harness Instagram auth bridge

This small Node/Hono service keeps the Meta app secret server-side and turns the Meta OAuth callback into a short-lived, one-time ticket for the desktop Host. It is a separate deployable package; do not mount it on the Agent remote-workspace server.

The package includes a Docker Compose deployment for a maintainer-operated public host. Point the DNS A/AAAA record for the bridge hostname at that host and allow inbound ports 80 and 443 on the host firewall. From this directory, copy `.env.example` to `.env`, replace the domain and Meta app values, set `SOCIAL_AUTH_BRIDGE_PUBLIC_BASE_URL` to the same `https://` origin, restrict the file to the operator account (`chmod 600 .env`), then run `docker compose up --build -d`. Caddy obtains and renews TLS certificates automatically and proxies HTTPS to the bridge; only Caddy is publicly exposed, while the bridge binds to `127.0.0.1:8080` for local health checks. Configure the exact callback `https://<bridge-hostname>/v1/instagram/callback` in the Meta app and set that public HTTPS origin in the desktop release configuration. The service exposes `/healthz` for the operator's health check.

The Compose volumes store hashed media-upload credentials, bounded temporary-media files/manifests, and Caddy's certificate state across restarts. OAuth state and one-time handoff tickets remain in process memory and expire after five minutes; restart or deploy exactly one bridge replica, because an interrupted sign-in must fail closed and be restarted in the app. The media store limits each upload to 1 GiB, total stored data to 2 GiB, and 32 leases with a two-hour maximum lifetime. Expired capabilities are rejected immediately, reads do not extend the lifetime, and the store removes expired files during startup, media requests, and a serialized background sweep at least once per minute while the bridge is running. V1 needs no SQLite database or separate object-storage account.

Do not enable request-body, query-string, or redirect-URL logging on the ingress. The OAuth callback query contains Meta's temporary authorization code, while the desktop callback contains only an opaque ticket. DNS, host firewall and container setup are maintainer operations; end users only use the preconfigured desktop bridge URL and make outbound HTTPS requests, with no router, tunnel, or hosting account setup.

## Meta pilot and Desktop configuration

Create or select the Meta app used by the pilot, add Instagram API with Instagram Login, and authorize eligible Creator or Business test accounts for `instagram_business_basic` and `instagram_business_content_publish`. Add pilot accounts to the app's test roles while it is in development; obtain the access/review configuration Meta requires before authorizing accounts outside those roles.

Set the app's OAuth redirect URI to the exact value `https://<SOCIAL_AUTH_BRIDGE_DOMAIN>/v1/instagram/callback`. In the bridge `.env`, use that same hostname for `SOCIAL_AUTH_BRIDGE_DOMAIN` and `SOCIAL_AUTH_BRIDGE_PUBLIC_BASE_URL`; the latter is only the HTTPS origin, without a path. Keep the app secret in this file on the bridge host and restrict access with `chmod 600 .env`. Start the Compose stack, then verify `curl --fail https://<SOCIAL_AUTH_BRIDGE_DOMAIN>/healthz` succeeds and Caddy has obtained a valid certificate.

Build the production Desktop with `SOCIAL_HARNESS_INSTAGRAM_AUTH_BRIDGE_URL` set to that same public HTTPS origin. The packager rejects production builds when this value is missing, non-HTTPS, or contains a path, query, or fragment. It is a public service URL, not a secret; never put the Meta app secret in Desktop build variables. Keep the origin identical in Meta's registered redirect URI, the bridge configuration, and the Desktop build. For a local disconnected-account smoke, use a Preview build and leave the bridge URL unset; it does not attempt a real Meta request.

The public DNS record and inbound ports 80/443 belong to the maintainer-operated host. Do not ask users to change router settings, create tunnels, expose local media, or provision a storage account. Before accepting pilot users, test a complete connect, profile/list, approved Reel upload, processing, publish, and disconnect cycle with the Meta test app and confirm expired media is removed from the persistent volume.
