# Version-specific release materials

This follows the third-party release gate in [the migration spec](social-harness.md). The strict gate remains closed until every production record has original publisher material and applicable source/build provenance. Do not weaken the gate, invent copyright holders or change package versions just to remove review records.

An npm archive can omit its original notice even when an immutable publisher source revision supplies it. When npm publishes neither a resolvable `gitHead` nor an exact source tag, a notice may be attributed through a recorded source comparison: verify the exact npm archive against its registry SRI, retain its SHA-256, identify an immutable source revision whose manifest declares the same package/version/license, and compare every shipped runtime file against that revision. Record non-runtime manifest differences explicitly. Keep the complete original notice verbatim with its immutable URL and SHA-256. A version number alone or a notice from a later incompatible source version is insufficient evidence.

An archive whose release commit is unavailable can also be tied to licensed publisher source through a prior archive: verify both exact registry SRIs, compare every shipped code/declaration/documentation file byte-for-byte, tie the prior archive's resolvable `gitHead` to the source revision containing the original notice, and verify that source changes consist only of the notice addition. Record all manifest differences and keep any changed dependency's own notice separately. This path is valid only for unchanged shipped software; do not attribute a different runtime implementation or invent the missing release commit.
